Post-Processing-Magic
Code wiki

A Windows desktop launcher, authenticated web UI and persistent serial worker for configurable ZIP preparation.

This reference describes the ZIP-only behavior accepted in 0.40 and documented in 0.41. Documentation explains the existing implementation; it does not add analysis engines, formats or new workflow behavior.

Read the boundaries first. The application orchestrates operator-selected KAPE and explicit PowerShell blocks. It does not interpret evidence contents, provide an isolation sandbox or establish forensic completeness. Runtime data and real evidence are not documentation inputs.

Open this HTML file directly in a browser. All navigation and styling work without a server, network, CDN, installation or JavaScript. Code paths are relative to the repository root and symbols are searchable identifiers, not executable links. This wiki ships independently of the source tree.

The desktop panel and server are separate processes. The server creates one worker with the multiprocessing spawn context; tool commands run in that worker's owned process tree. Trace one ZIP preparation

  1. Configure deliberately. Storage, ModeStore and ConfigurationTransfer hold tools, ordered steps and limits. Catalogue readiness uses compile_plan(); incomplete, conflicting or unsupported modes cannot start.
  2. Freeze admission. JobService.begin() checks worker/admin state, unique mode slot, destination, drain/cleanup admission and outstanding-job count. It captures commands, tool hashes/versions, direct KAPE provenance, locale, case/device, destination and limits into config_json. New jobs always permit high compression; old snapshots are not rewritten.
  3. Finalize input. Uploaded bytes are size/space checked and hashed with SHA-1/SHA-256, written to upload.part and atomically renamed before queuing. Client filenames become bounded metadata, never host storage paths. JobService.local() records file identity; the worker rechecks, locks and hashes the reference before extracting.
  4. Claim once. QueueControl.claim() selects the oldest eligible queued job under BEGIN IMMEDIATE. Pause, drain and cleanup checks share that transaction. A queue does not imply parallel processing.
  5. Validate before extraction. extract_checked() bounds central-directory allocation and validates the entry set before writing. Streamed extraction is bounded and cancellation-aware. Archive-relative names are preserved. Input metadata inventory is collected before configured commands run.
  6. Execute the frozen sequence. process_job() resolves each relative working directory. execute() checks executable SHA-256 and captured KAPE files, launches with shell=False, assigns the suspended child to a Job Object and then resumes it. PowerShell blocks are separate invocations: cd cannot change the next block's initial directory.
  7. Persist real progress. Status/log events are stored in SQLite; SSE consumers resume with a numeric cursor. Completed block counts are known, arbitrary progress inside a tool is not. Cancellation or timeout closes the owned tool Job Object and remaining descendants.
  8. Describe and package. prepare_report() records hashes/inventory, timing/exit/tool metadata and output paths/counts. make_archive() packages user outputs and sanitized reports, hashes the finished archive and updates external reports. A later explicit ArchiveQueue.request() can archive a successful old run without rerunning commands.
  9. Serve or retain. Views expose case/device/date/ID, status, terminal and available downloads. Source metadata distinguishes retained uploads from local references. Cleanup is a separate previewed and confirmed operation.

Status and restart semantics

The usual transition is uploading → queued → running → succeeded. Terminal alternatives are failed, cancelled and interrupted. Archive requests have their own state. JobStore.recover() marks unfinished supported jobs interrupted on startup, including queued jobs; it never silently retries them. Historical unsupported-workspace records remain passive instead of being reactivated or deleted.

When exactly one drive-letter directory is present, the worker may resolve the configured source drive to that directory. It records source_resolution and an effective configuration. Archive names are not renamed. Ambiguous or invalid layouts fail explicitly.

Configuration schema 4

ConfigurationFile in config_transfer.py declares format = "post-processing-magic.configuration", schema_version, app_version, exported_at, tools, modes and limits. Exports emit schema 4. Schemas 1–3 remain controlled inputs; retired legacy fields require an explicit warning and confirm_legacy_fields. Schema 4 rejects retired fields.

ConfigurationTransfer.preview() validates IDs/names, slots and tool references; computes merge/replace changes; checks path availability; and stores a 600-second ticket with a fingerprint of current configuration. apply() requires replace/legacy confirmations, uses BEGIN IMMEDIATE, rejects intervening configuration changes, backs up configuration and writes atomically. Expired or stale previews need a new preview. Import and Save never execute commands.

Mode contract

ModeDraft owns name, description, evidence_format, effort, source_folder, extract_folder, output_folder, command_reference and ordered steps. Only ZIP is executable. Extraction and output may not overlap. CommandStep carries ID/name, explicit type, tool reference or script, parameters, relative working directory and integer timeout.

ModeStore.save() enforces unique format/effort slots transactionally. Existing duplicate slots remain visible conflicts rather than being silently reassigned. Storage.delete_tool() rejects removing a referenced tool and names the affected modes. Tool-path availability is not approval of an imported workflow.

Integrity and resource boundaries

Paths and handles

validate_local_path() checks syntax; ModeDraft.job_relative_folder() restricts run-relative folders; no_links() rejects reparse/link traversal; registered_root() checks registration/ownership. locked_input() and input_identity() pin/check sources at use time. A suffix or path check alone proves neither valid contents nor protection against a privileged administrator.

ZIP limits

Defaults: 50 GiB uploaded, 2,000,000,000,000 extracted bytes. zip_safety.py also caps ZIP entries at 200,000 and central-directory allocation at 64 MiB, bounds depth/name length, rejects duplicate/file-directory conflicts and retains a 512 MiB disk reserve. Absolute/UNC/drive paths, traversal, ADS, reserved Windows names, links/special files and encrypted entries are rejected. Extraction does not recursively process nested ZIPs.

New jobs permit compression ratios above 1000:1 with a recorded notice. Other path/count/size/disk limits still apply. High compression does not add encryption support or make every possible archive acceptable.

Execution and direct provenance

The compiler supports at most one offline KAPE block plus explicit PowerShell blocks, or PowerShell-only workflows. KAPE accepts validated --msource, --mdest, --module and optional --gui. Registering a tool does not create a generic runner. Tools and PowerShell inherit administrator rights; they are operator-controlled code, not a sandbox.

kape_manifest.py caps selected modules (64), files (128), single-file reads (64 MiB), total reads (256 MiB), module text (1 MiB), scanned entries (10,000) and depth (16). Only supported literal relationships are captured. Changed captured files block command start. Unresolved references are recorded; they are neither silently verified nor a complete dependency preflight.

Logs and reports

The worker bounds command/job output around 16 MiB; excess output is discarded with a notice. SQLite keeps a 65,536-character tail with bounded event chunks. command.log is not an unlimited transcript.

collect_inventory() defaults to 500,000 scanned entries, 10 seconds and 20,000 stored file paths. Projection/rendering impose additional output bounds and identify partial/truncated metadata. metadata_report() is a recursive, detached, idempotent allowlist for new and retrieved historical reports. It excludes command lines/scripts, terminal output and content findings. Missing historical hashes are not manufactured by rereading old evidence.

User outputs remain in archives even if their basenames resemble old app artifacts; filtering excludes concrete app-owned paths. The external report can show final ZIP hashes; an embedded report cannot include the hash of the ZIP containing itself.

Original and result downloads differ

SourceAccess.stream() consumes a ticket, opens a checked read handle and verifies the identity recorded at authorization. It rejects hardlinks/reparse changes and streams 1 MiB chunks. A SQLite source-stream lease expires after 300 seconds and is renewed every 30 seconds independently of client demand. Completion/disconnect/error releases the handle/lease. Cleanup admission checks live source leases.

Result ZIP tickets also expire after 120 seconds and are one-use, but results_router() returns FileResponse after availability checks. That path does not use the original-source lease mechanism. Do not claim all downloads have identical identity/cleanup guarantees.

Cleanup and trust

Cleanup's 10-minute preview fingerprints a bounded manifest; apply rechecks it, uses cleanup_state to block new claims/admission and verifies deletion targets. Local originals/history/settings remain protected. Cache, uploaded original copies and result/report deletion are separate categories.

Diagnostics include allowlisted status and normalized known technical events, not arbitrary raw tool/server logs. The preview is the prepared export. Local hashes are integrity metadata, not proof of provenance or legal admissibility. This wiki documents implementation; it is not a security audit or certification.

Extend a workflow without application changes

  1. Provide/license programs separately. In Settings → Tools, save and inspect the absolute server path. This check does not execute the tool or approve a profile.
  2. In Settings → Modes, use a free ZIP/effort slot and separate relative extraction/output folders. ZIP C/... extracted to Targets becomes Targets/C/....
  3. Add ordered supported steps. KAPE references a tool ID with separate parameter text; omit the executable name from parameters. PowerShell is an explicit step with no tool reference. Set working directory and timeout deliberately.
  4. The current compiler permits one KAPE block at most. A parameter shape is --msource .\Targets\C --mdest .\PostMortem --module YourLocalModule. Substitute an actually configured local module; this example is syntax, not a supplied or approved profile.
  5. Each PowerShell block uses -NoProfile -NonInteractive -EncodedCommand. Encoding is transport, not encryption or isolation. The wrapper stops on errors and propagates native exit codes. Create required relative directories before later blocks use them; arbitrary commands retain operator responsibility.
  6. Save, export schema 4 and inspect it. On another workstation preview import, resolve conflicts, confirm intended replacement/legacy omission, and recheck paths. Do not treat tokens/databases as portable configuration.
  7. Validate first with self-created ZIPs and harmless scripts/programs. A deliberate Run captures that job's plan; later settings do not rewrite it.

New formats, general tool adapters, parallel workers and content parsers require separate product/code/validation work; relabelling an extension or importing unsupported fields cannot enable them.
